補助資料: 01 Transformer bottleneck / 02 Physics-Attention Transolver

Transformer は何をしていて、Transolver は何を変えたのか

自然言語の「単語どうしの関係を見る」仕組みを、CFDやPDEのメッシュ点にそのまま使うと何が重くなるのか。TransolverのPhysics-Attentionが、点を少数の代表ベクトル、つまり物理tokenへ集約して処理する流れを図解します。

1. テキストTransformerの基本フロー

Transformerの中心はSelf-Attentionです。各tokenが「自分は他のtokenの情報をどれくらい参照すべきか」を重みとして計算し、文脈を含んだ表現に更新します。

1

Tokenize

文を処理単位へ分ける。自然言語では単語やsubwordがtokenです。

圧力が後流で変化
2

Embedding

tokenを数値ベクトルへ変換し、順序や位置の情報を足します。

3

Q / K / V

各tokenからQuery, Key, Valueを作る。Queryは「何を探すか」、Keyは「何を持つか」、Valueは「渡す中身」です。

QKV
4

Attention

QとKの類似度を全token組み合わせで計算し、softmaxで重みにします。

5

Update

重みに従ってValueを混ぜ、各tokenを文脈込みの表現へ更新します。

out_i = Σ attention(i,j) · V_j

2. tokenの意味が変わる: 文から物理メッシュへ

CFDやPDEでは、tokenを「単語」ではなく「メッシュ点・表面点・格子点」と見なします。各点は座標、法線、圧力、速度、材料量などの特徴量を持ちます。

自然言語のtoken

単位単語、subword、記号
位置文中の順序が強い意味を持つ
Nの規模数十から数千tokenが典型
関係遠い単語との関係も文脈として重要

物理モデルのtoken

単位メッシュ点、表面点、セル、観測点
位置3D座標、境界、流れ方向、近傍構造が重要
Nの規模数万から数十万点になりやすい
関係近傍、剥離、後流、境界層など局所性と構造が効く
同じSelf-Attentionでも、入力の世界が違います。 テキストでは「文脈の全体参照」が強みですが、物理点群では全点を同じ密度で比較するより、局所的・構造的な相互作用をどう圧縮して扱うかが重要になります。

3. 標準Attentionを物理メッシュへそのまま使う弊害

標準Self-Attentionは、N個の点すべての組み合わせを比較します。点数が増えると、Attention行列だけで計算量とメモリが急増します。

主な問題

計算量: N点どうしで比較するため、計算もメモリも O(N²) になります。

幾何の扱い: メッシュは不規則で、点密度や境界条件が場所ごとに違います。単純な順序位置だけでは表しにくい構造があります。

物理の局所性: 圧力・速度・熱などは近傍や流れ構造に強く依存します。遠い全点を同じ土俵で密に比較するのは非効率です。

N² 標準Attentionのペア比較
160B N=400k のペア数
局所性 近い点や流れ構造が重要

4. Transolverの発想: 点を少数のphysics tokenへ集約する

Transolverは、点どうしを直接すべて比較する代わりに、各点を少数のslice、つまり「一時的なまとめ先」へゆるく割り当てます。ここで説明する Slice → Aggregate → Attend → Deslice は、Transolver全体ではなくPhysics-Attentionモジュールの中身です。

生の入力

座標、法線、境界条件、物理量などの元データ。

→
MLP埋め込み

生の入力を、各点の特徴ベクトル x: (N, C) へ変換する前段。資料のNumPy例ではここを済ませた前提です。

→
Physics-Attention

この資料で詳しく追う部分。Slice、Aggregate、Attend、Desliceで点群を更新します。

位置づけ: 実際のTransolverでは、MLP埋め込みとPhysics-AttentionがTransformer blockの構成要素として使われ、残差接続、正規化、Feed Forward Networkと組み合わされます。そのblockを複数層積み重ねて、最終的な物理量を予測します。

Slice

点特徴 X から、各点がどのsliceに属するかを表す重み S を作ります。分け方は固定ルールではなく、学習パラメータ W_project が決めます。

S = softmax(X W_project)

Aggregate

sliceごとに点特徴を重み付きで集め、少数のphysics token Z を作ります。各tokenは、そのsliceが代表する物理状態の要約です。

Z = normalize(S)^T X

Token Attention

全点Nではなく、代表token M個だけでAttentionします。ここが計算量削減の中心です。

A = softmax(QK^T / √d)

Deslice

更新されたtokenを、Sliceで使った重みによって各点へ戻します。点ごとに混合比が違うため、隣り合う点でも異なる更新値になります。

X' = S Z'

5. 実際の処理のshapeで追う

2本目の資料では、N=1000点、M=8 slice、C=32特徴次元のtoy dataで、Physics-Attentionの中身をNumPy風に確認しています。Cは「点1個を表す数値ベクトルの長さ」です。重要なのは、重いAttentionが N×N から M×M へ置き換わることです。

段階 主な配列 shape 意味
入力 X (N, C) N個のメッシュ点それぞれがC次元の特徴量を持つ。
Slice slice_weights (N, M) x @ W_project をsoftmaxし、各点がM個のsliceへどれくらい属するかを出す。各行は合計1。
Aggregate tokens (M, C) slice_weights.T @ x で、N点の情報をM個のphysics tokenへ重み付き平均で集める。
Attention attention (M, M) 代表tokenどうしの相互作用を学習する。N×Nではない。
Deslice X_updated (N, C) slice_weights @ z_prime で、更新されたtoken情報を各点へ戻す。出力shapeは入力と同じ。
Full Transolver層では何が足されるか: 実際の層では、このPhysics-Attentionの前後にMLP、残差接続、LayerNorm、Feed Forward Networkが加わり、通常のTransformer blockのように複数層を積みます。

6. Physics-Attention Q&A: よくあるつまずき

Q&Aで確認したポイントを、他の人が同じところで詰まらないように補強しました。ここでは x は各点の特徴ベクトル、M はslice数、C は特徴次元です。

Q1. Sliceはどうやって各点を分割するの？学習するの？

分割の基準は W_project という学習パラメータが決めます。

slice_logits = x @ W_project
slice_weights = softmax(slice_logits, axis=1)
  • 固定ルールではなく、タスク全体の損失が小さくなるように W_project が自動学習されます。
  • 単純な空間位置だけでなく、座標・法線・境界条件・圧力傾向などを含む特徴空間での類似度に基づいて分かれます。
  • 学習後には「前縁高圧域」「後流領域」のような物理的に意味のある構造がsliceに対応する可能性があります。

Q2. Aggregateで「集める情報」とは何か？

各点の特徴ベクトル x を、slice重みで加重平均して集めます。

tokens = slice_weights.T @ x
  • slice j に強く属する点の特徴を重点的に集約したベクトル z[j] ができます。
  • 結果として「このsliceが代表する物理状態の要約」になります。
  • 何を基準にまとめるかは、W_project と前段のMLPが学習します。

Q3. Desliceで「各点に戻す」とは？

Attention後の更新済みtokenを、各点のslice重みの比率でブレンドして受け取ります。

x_prime = slice_weights @ z_prime
  • 各点は、自分の slice_weights に応じて複数tokenの情報を混ぜて受け取ります。
  • slice重みは点ごとに異なるため、隣り合った点でも異なる混合比になります。
  • この「重みつきで戻す」処理が、空間的に連続した予測値の変化を生みます。

Q4. SVMやK近傍法、K-meansと何が違う？

特徴空間の類似度を使う点は似ています。ただしTransolverの目的は分類や近傍探索ではなく、代表token間の相互作用を学習することです。

  • ソフト割り当て: KNNやK-meansは1点を1グループに完全帰属させがちですが、Transolverは1点が全sliceへ確率的に属します。
  • 境界領域に強い: 境界付近の点を複数sliceにまたがって扱えます。
  • Attentionはグループ間: グループ内を細かく分析するのではなく、「前縁sliceと後流sliceがどう関係するか」をtokenレベルで捉えます。

全体の流れを一言で

各点をゆるく割り当てる
代表token間の相互作用を学習する
重みに応じて各点へ再配分する
ステップ 処理 shape変化
Slice x @ W_project → softmax (N,C) → (N,M)
Aggregate slice_weights.T @ x (N,M)×(N,C) → (M,C)
Attend token間のAttention (M,C) → (M,C)
Deslice slice_weights @ z_prime (N,M)×(M,C) → (N,C)

8. 初学者向けの読み替え

式だけを見ると難しく見えますが、処理の意味は「全部を直接比べるのをやめ、代表を介して必要な相互作用を運ぶ」ことです。

Transformer

各tokenが他の全tokenを見ます。文章では、離れた単語の関係も文脈として効くため強力です。

物理メッシュでの困りごと

点が多すぎます。しかも、重要な関係は単純な文順ではなく、近傍、境界、流れの構造に現れます。

Transolver

点を少数の物理tokenへゆるく集約し、そのtoken間でAttentionします。結果を各点へ戻すので、点ごとの予測に使えます。

Attention どの情報をどれくらい参照するかを重みで決める仕組み。
Token Transformerが処理する単位。物理ではメッシュ点や代表状態にも対応する。
Soft assignment 1点を1グループへ固定せず、複数グループへの所属度として扱うこと。ここでは「ゆるい所属」と考える。
Bottleneck 情報を一度小さい表現へ圧縮する箇所。計算量を下げる一方、必要情報を残す設計が重要。
Slice 点を一時的にまとめる先。空間を固定的に切る箱ではなく、特徴に応じて学習される所属先。
W_project 各点をどのsliceへどれくらい割り当てるかを決める学習行列。
Physics token sliceに集めた点情報の代表ベクトル。前縁、後流、境界付近などの物理状態を要約しうる。
